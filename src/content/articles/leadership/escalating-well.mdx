<InShort>
Write the case for a reader who has five minutes and no context. Lead with **one sentence**: what fails, where, since when, and the impact. Then the **identifiers**: task or reference IDs, exact error text, time with time zone, versions. Then the **evidence**: the right bundle for the layer that failed, uploaded as the KB describes (<KB id={140731} />). Then **what you tried**, including what made it worse. Set severity by business impact, not frustration, and name one contact who can make changes.
</InShort>

## A template

```text
Summary:    <what fails> in <component/domain> since <time UTC>. Impact: <who/what is blocked>.
Versions:   VCF <x>, SDDC Manager <x>, VCF Operations <x>, vCenter <x>, NSX <x>
IDs:        Task <id>, reference <id>, failed step <name>
Error:      <exact text, copied, not retyped>
Evidence:   <bundle names and upload reference>
Tried:      <step> -> <result>; <step> -> <result>
Changes:    <anything changed in the last 7 days>
Contact:    <name, hours, can approve changes: yes/no>
```

## Choosing the bundle

| Failure layer | Bundle |
|---|---|
| SDDC Manager workflow | `sos --sddc-manager-logs --zip` (<KB id={385749} />) |
| Hosts, vCenter or NSX involved | `sos --collect-all-logs` with the domain |
| 9.1 runtime, fleet or depot | Add `--vcf-mgmt-svcs-logs`, or the fleet lifecycle bundle (<KB id={402476} />) |
| VCF Operations | Its Control Panel bundle |
| UI only | A browser HAR file plus the VCF Operations bundle |

See [health checks and SoS](/vcf/library/day-2/health-checks-sos/) for details.

<Callout type="field">
Before sending, read the case as if you were the support engineer. If you would have to ask a question to start work, answer it in the case now.
</Callout>

## Habits that help

- **One problem per case.** Two problems in one case get half an answer each.
- **Update the case** when anything changes, even "no change after restart".
- **Close the loop**: record the fix and the KB in your own knowledge base when it's solved.
