<InShort>
VCF 5.2 introduced the **Import Tool** (`vcf_brownfield.py`, run on SDDC Manager). It could **convert** a vSphere environment into a management domain, or **import** a vCenter as a VI workload domain. In 9.x the same two outcomes are built in. The **VCF Installer** converges existing vSphere, VCF Operations, vCenter and NSX into a new fleet, deploying whatever is missing. An existing fleet can **import** a vCenter as a workload domain from VCF Operations, deploying NSX if needed. Success depends on version pairs, which include back-in-time rules, and on topology: no Enhanced Linked Mode, supported distributed switches, and storage and network settings that pass validation.
</InShort>

## Version rules worth checking first

For the 9.0 releases, the VCF blog gives these minimums:

- **Aria Suite Lifecycle** at 8.18 Patch 2 or later, and **Aria Operations** upgraded to VCF Operations 9.x.
- **9.0.0** needs vCenter and ESX at 9.0. It does not support NSX in convergence.
- **9.0.1 and later** accept vCenter 8.0 U1a or later and ESX 8.0 U1a or later. With NSX, NSX must be 4.1.0.2 or later.

For 9.1.0 sources, the back-in-time rules apply (<KB id={450972} />). vSphere 8.0 U3 to U3i can upgrade, converge or import. 8.0 U3j and U3k can only **import**, which onboards the environment into a 9.1 fleet without changing its builds. Upgrade and converge for those builds arrive in a later 9.1.x patch.

## The assessment is the project

1. **Assess.** Versions, Enhanced Linked Mode (must be removed), VDS versions, storage type, network settings and host defaults that must match VCF expectations.
2. **Remediate** what validation flags. Plan the most time for this step.
3. **Convert or import.** Run it after remediation.
4. **Bring lifecycle in line.** Imported domains are then upgraded through VCF like any other. Hosts that were added to SDDC Manager through brownfield import may need out-of-band steps, documented in <KB id={384976} />. A known failure when upgrading imported domains is covered in <KB id={430524} />.

## VVF and VCF

vSphere Foundation can converge into a VCF fleet as well. In 9.1, the management services are mandatory for VCF but optional for VVF (<KB id={440630} />). A VVF estate without them has no unified fleet management for passwords, certificates or backup. That is a strong argument for deploying them when the licence allows.

<Callout type="field">
Don't scope a convergence project on assumptions such as "we don't use ELM", "all switches are the same version" or "NSX is only in the lab". Gather the facts with a script before the scoping call.
</Callout>

## Pitfalls

- **Assuming 9.0.0 behaviour.** Convergence rules changed in 9.0.1 and again in 9.1. Read the release notes for your exact target.
- **Breaking Enhanced Linked Mode on the day.** Unlinking vCenters has its own impact on users, roles and tools. Do it in an earlier change.
- **Treating import as an upgrade.** Import onboards the environment at its current versions. Upgrades are separate steps afterwards.
