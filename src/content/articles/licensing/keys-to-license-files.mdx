<InShort>
A VCF 9.x subscription doesn't turn every key into one file. The add-ons follow different routes, <AsOf date="2026-11-06" />.

- **In the VCF file:** the VCF or VVF primary license, vSAN TiB and Private AI Foundation with NVIDIA cores. Assign the primary to vCenter first.
- **In a separate signed file:** vDefend 9.1 and Avi 32.1.1. Convert the key on the Support Portal, then license through License Hub and the Avi Cloud Console.
- **Depends on the order line:** Live Recovery. A standalone SRM line is a 25-character key, and subscriptions run through the Live Recovery console.
- **Not stated:** Data Services Manager, which moved into TrueSource on 4 Nov. The Broadcom documents cited here don't give its route (checked 6 Nov 2026), so get it in writing before you plan around it.
- **Still a key:** Tanzu Platform, added in Tanzu Hub.
</InShort>

<Callout type="note" title="Corrected on 6 November 2026">
This note used to say vDefend, Avi, Tanzu Platform and DSM all keep keys and that Live Recovery is SaaS, as Broadcom's June 2025 post did. vDefend 9.1 and Avi 32.1.1 have since moved to signed files, Live Recovery now has an on-premises offering, and DSM's route has been an open question since 4 Nov.
</Callout>

## How a key estate becomes a file estate

In 5.x you hold 25-character keys and type them into products. In 9.x, [FAQ Q12 and Q14](https://www.vmware.com/docs/vmware-cloud-foundation-9-1-general-faqs) say license files from the VCF Business Services console go into VCF Operations and are assigned to vCenters. vCenter 9 has no key field (<KB id={404155} />). This route documents no key conversion: attempts to upgrade 8.x keys on the Support Portal return "No data available to upgrade" (<KB id={452764} />), and FAQ Q10 lets 5.x environments keep their keys beside 9.1.

Capacity pools by product and Site ID into a default license. Broadcom's [Private License Files guide](https://vcf.broadcom.com/vcf/clm/assets/VCF-9.1-Licensing-Private-License-Files.pdf) gives the arithmetic: 500 VCF cores also bring 500 TiB of vSAN in a separate license, and a 200 TiB add-on takes that license to 700 TiB. In 9.1 the file sits with a [license server beside VCF Operations](/vcf/library/licensing/license-server/). Connected mode [sends usage and fetches a new file every 24 hours](https://blogs.vmware.com/cloud-foundation/2026/05/18/vcf-9-1-licensing-programmatic-centralized-and-built-to-scale/), and disconnected mode [repeats the exchange by hand](/vcf/library/licensing/180-day-cycle/) at least every 180 days.

The [9.1 overview](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/licensing/licensing-overview.html) names only two add-ons the console manages, so everything else has its own route.

## What each add-on does

For what each edition entitles you to, use [the entitlement matrix](/vcf/library/value/using-what-vcf-includes/). This table covers delivery only.

| Add-on | How 9.1 delivers it | What changes from a 5.x key | Documented? |
|---|---|---|---|
| vSAN TiB | VCF file. [Applies to every vSAN cluster](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/licensing/licensing-overview/add-on-licenses-in-vcf-9-0.html) under the vCenter, or to one cluster by override from 9.1 | No key. Add-on TiB pools with the TiB included in VCF | Documented |
| Private AI Foundation | VCF file, counted in cores | No key. TechDocs says that from 3 Nov 2025 you "might also receive" it, so check the console | Documented; entitlement in [conflict 4](/vcf/library/value/using-what-vcf-includes/) |
| vDefend Firewall | [Signed file through License Hub](https://techdocs.broadcom.com/us/en/vmware-security-load-balancing/vdefend/vdefend-firewall/9-1/release-notes/vmware-vdefend-91-release-notes.html) from vDefend 9.1. Usage due from the hub every 180 days | Key must be converted on the Support Portal before assignment | Documented |
| Avi Load Balancer | [Signed file](https://techdocs.broadcom.com/us/en/vmware-security-load-balancing/avi-load-balancer/avi-load-balancer-vmware-cloud-foundation/9-1/build-and-deploy-avi-91/license-management-for-avi-load-balancer.html) from 32.1.1, through License Hub, or registered directly if a Controller can't run a hub. The console issues an activation code when connected and a signed file when disconnected | Same conversion, with a 90-day grace period to move to the new format on the upgrade to 32.1.1 | Documented. The [Licensing Tiers page](https://techdocs.broadcom.com/us/en/vmware-security-load-balancing/avi-load-balancer/avi-load-balancer-vmware-cloud-foundation/9-1/nsx-advanced-load-balancer-editions.html) (18 June) still says "License key" |
| Live Recovery, standalone SRM (VCF-SRM) | 25-character key from the Support Portal, entered in the product (<KB id={429032} />, <KB id={427391} />). It doesn't appear in the console | Key stays, but needs reassigning after a major upgrade (<KB id={376866} />, 8.x to 9.0) | Documented for 9.0 |
| Live Recovery, subscription | Live Recovery console, or an [offline key tied to one site pair](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/fleet-management/vcf-fleet-disaster-recovery/fleet-disaster-recovery-task-library/implementation-of-vsphere-replication-for-the-management-domain/configure-failover-of-the-sddc-management-components-for-the-management-domain/protected-site-configuration-tasks/assign-licenses-to.html) (<KB id={428834} />, 9.0.x; console scope in <KB id={429032} />) | Advanced Cyber Compliance runs to the end of its term, then the buyer can move to Live Recovery (FAQ Q86) | Not for the on-premises line named in FAQ Q87 and the [feature comparison](https://www.vmware.com/docs/vmware-cloud-foundation-9-1-feature-comparison-and-upgrade-paths) p17 (both 4 Nov) |
| Data Services Manager | Not stated since the [FAQ Q84](https://www.vmware.com/docs/vmware-cloud-foundation-9-1-general-faqs) move to TrueSource data services (checked 6 Nov) | Pre-9.0: "No license enforcement" (<KB id={406836} />). 9.1 checks the vCenter license | Open |
| Tanzu Platform | Key for Elastic Application Runtime, [validated and added in Tanzu Hub](https://techdocs.broadcom.com/us/en/vmware-tanzu/platform/tanzu-hub/10-4/tnz-hub/foundations-manage-license-keys.html) | No change documented | Hub 10.4 only |

Three of those rows need a closer reading.

**DSM.** The June 2025 post put it on keys, and the [May 2026 post](https://blogs.vmware.com/cloud-foundation/2026/05/05/vmware-data-services-manager-9-1-automating-the-modern-databases-that-drive-ai-and-private-cloud/) says only that it's licensed apart from core VCF. The [DSM 9.1 guide](https://techdocs.broadcom.com/content/dam/broadcom/techdocs/us/en/pdf/vmware/dsm/vmwdsm/vmware-data-services-manager-9-1.pdf) (25 Sep, p124-125) has alerts that read the vCenter license: `LicenseInsufficient` means the license doesn't include DSM, and the fix for `VCENTER_LICENSE_INVALID` is a VCF primary on that vCenter. Searching that guide turns up no procedure for entering a DSM license. The [Advanced Services page](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/vcf-advanced-services.html) (5 Nov) still lists VMware Data Services Manager and doesn't mention TrueSource, while the feature comparison (4 Nov, p17) lists TrueSource Data Services among the add-ons.

**vDefend on the way through.** The [9.1.1 notes](https://techdocs.broadcom.com/us/en/vmware-security-load-balancing/vdefend/vdefend-firewall/9-1/release-notes/vmware-vdefend-911-release-notes.html) give two expiry behaviours. After evaluation or trial expiry, a firewall in an unlicensed state "allows all traffic". After a subscription expires, there are 90 days' grace, and then rules keep protecting workloads but you can't create or edit them. They don't say which one applies to an upgrade with an unconverted key.

**Live Recovery keys.** Keys generated on or after 20 April 2026 fail as "Invalid license key" on older appliances. <KB id={438925} /> sets the minimums: 9.0.2.4 from the 9.0.1 to 9.0.2.3 line, 9.0.5.1 from 9.0.3 to 9.0.5, and 9.1.0.0100 for Protection and Recovery 9.1.0.0. If you renew during the migration, you can hit this before you touch anything else.

## The order of work

Steps 1, 2 and 7 are this site's advice. The others follow the sources above, and the [upgrade note](/vcf/library/licensing/licensing-through-upgrades/) has the core sequence in full.

1. **Sort the order document by route,** using the table. Name who can sign in to each of the Business Services console, Support Portal, Avi Cloud Console and Live Recovery console for the right Site ID.
2. **Ask Broadcom in writing** how DSM under TrueSource and the on-premises Live Recovery line are delivered. Do this before the change window.
3. **Convert vDefend and Avi keys, and stand up License Hub,** before those products reach vDefend 9.1 or Avi 32.1.1. Broadcom dates both changes from those versions, so this site reads a stop at VCF 9.0 as keeping the keys; confirm that for your order. Broadcom's notes name both License Hub 5.1.2 and 2.0, so check which your NSX release needs.
4. **Bring up VCF Operations 9, register it and add licenses to the license server.** Upgraded components [go into evaluation](https://www.vmware.com/docs/vmware-cloud-foundation-9-1-general-faqs) (FAQ Q11), which [lasts up to 90 days](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/licensing/licensing-overview/licensing-model.html).
5. **Assign the primary to each vCenter, then the add-ons.** The add-on page requires that order. If you run several VCF Operations instances, split in the console first: one allocation can't serve two instances (<KB id={437242} />). That KB's split step names only the default license, so check the vSAN license separately.
6. **Check Live Recovery on each site pair.** Reassign the key if the state shows evaluation or expired, and check the appliance version against <KB id={438925} />. Offline keys are created per site pair, and closing the request window invalidates the change request key.
7. **Put every clock in one calendar.** A disconnected VCF Operations and a License Hub each have their own 180-day usage cycle, in different consoles.

<Callout type="analysis" title="This site's reading">
The phrase "license file" now covers two unrelated estates with separate consoles, appliances and reporting. A project plan with one licensing line will miss the second. Treat the DSM rows as a question for Broadcom: the guide's alerts suggest the product reads its state from vCenter, but that's inference and doesn't tell you what the console will issue.
</Callout>

This isn't legal or purchasing advice. Your order document and Broadcom's program documentation decide what you hold.
