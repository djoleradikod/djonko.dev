<InShort>
The docs call it the **reporting mode**, and there are only two. **Connected**: VCF Operations reaches the console over HTTPS, registers with an activation code, and sends usage daily. In 9.1 it also refreshes licenses automatically every 24 hours. **Disconnected**: you carry a registration file to the console and a license file back, then repeat the usage cycle by hand at least every 180 days. 9.1 adds a **verification file** and a **confirmation file**, which is valid for only three hours. You can switch modes later in either direction. Air-gapped sites need one VCF Operations per isolated environment (<KB id={404155} />).
</InShort>

## Connected registration in 9.1

1. Prerequisites: the License Server is deployed, the vCenter adapter is running, and internet access or a proxy is set in **Global Settings > Network Settings**.
2. **Manage > Licensing > Licenses & Registration > Register & License VCF Operations**, then choose **Connected**.
3. Start on the console card, sign in, choose the **Site ID**, name the instance and **generate the activation code**.
4. Paste the code into VCF Operations and **Activate**.
5. On the console, add licenses for each License Server: at least one primary, split capacity if needed.
6. Assign a primary license to each vCenter. Leave updates on **Automated**.

In 9.0 the flow is similar from **License Management > Registration**, without the License Server steps.

## When registration fails

- **Check reachability from every node**, including the primary: `curl -v telnet://vcf.broadcom.com:443` and the same for `eapi.broadcom.com` (<KB id={431546} />, <KB id={404593} />).
- **A 407** means proxy credentials. **A 401 `invalid_client`** means the activation code expired or is wrong: generate a new one (<KB id={435664} />).
- **Greyed-out registration options** usually mean you are not logged in as the local `admin` (<KB id={416864} />).
- **If the network can't be fixed quickly**, register in disconnected mode now and switch later. Disconnected mode needs no activation code (<KB id={432201} />).

<Callout type="field">
For disconnected customers, automate the usage cycle. William Lam's scripts and PowerShell module use the VCF Operations and console APIs to generate and import files. A scheduled reminder at 150 days, with a named owner, is the minimum.
</Callout>

## Pitfalls

- **Reusing a registration file from another instance.** It fails. Each instance generates its own.
- **Replacing VCF Operations in a dark site** without removing the old adapters and appliance first. Follow the replacement procedure (<KB id={436542} />).
- **Assuming one VCF Operations can license several dark sites.** Central licensing across disconnected sites is not supported.
