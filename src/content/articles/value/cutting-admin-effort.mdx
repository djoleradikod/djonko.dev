## Where the hours come back, ranked

[Vivek Rau's chapter in the Google SRE book](https://sre.google/sre-book/eliminating-toil/) defines toil as manual, repetitive, automatable, tactical work with no enduring value that grows with the service. Growth is what makes it a cost line: ten vCenters whose certificates expire on different dates are ten jobs a cycle. Google's SRE organisation aims to keep toil below 50% of each engineer's time, and a platform team can borrow that target. The split below is this site's reading of the pages linked after it.

| Task | Hours to count as saved | Stays on the team's books |
|---|---|---|
| Certificate renewal | Hands-on renewal of leaf certificates that auto-renew | CA set-up, root and intermediate certificates, anything an external CA signs, components outside VCF, failed renewals |
| Management lifecycle | Separate tools and binary handling | Change approval, patch order, validation |
| Licence reporting | The manual update, in 9.1 connected automated mode | Registration, disconnected uploads, add-on keys, watching that the daily update still runs |
| Password work | Logging in to each component to change a password | Rotation schedules, ESX rotation, break-glass procedures, vaulting, outbound alerts |
| Known-issue checks | Time spent looking for what applies, if you recorded it | Deciding what to fix and when |
| Host configuration | Finding drift by hand on vSphere Configuration Profile clusters | Defining the standard and fixing the drift |

Certificates are the largest change, and your CA decides whether you get it. [VCF Operations can't auto-renew certificates signed by an external CA](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/fleet-management/certificate-management-9-0/set-up-automatic-renewal-of-certificates-in-vmware-cloud-foundation.html), or any root or intermediate. The [blueprint also wants default CA-signed certificates on management components replaced by an enterprise CA's before production](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/fleet-management-blueprint/certificate-management/recommendations-for-vcf-certificate-management.html). Put together, an enterprise PKI other than Microsoft CA gets the trust baseline and keeps the manual work. That's an inference from those two pages, so settle the CA before promising this saving; the [certificates note](/vcf/library/day-2/certificates-in-9/) walks through the choice and treats OpenSSL as test and development only. Manual jobs do shrink: [9.1 runs up to 10 same-type operations in one batch, in sequence](https://blogs.vmware.com/cloud-foundation/2026/10/14/managing-certificates-at-scale-with-vmware-cloud-foundation-9-1-1/), as Firth and Hah describe, and the [9.1.1 release notes report concurrent replacement tasks failing after 2 hours](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/release-notes/vmware-cloud-foundation-9-1-1-0-release-notes/vcfoperations-9-1-1-0-release-notes.html), so don't run them side by side. VCF Operations 9.1 also [reaches VCF 5.2 components for certificates](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/release-notes/vmware-cloud-foundation-9-1-0-0-release-notes/what-s-new/whats-new-vcf-ops.html), so take the 5.x baseline before that integration changes the work.

Lifecycle gets one console and keeps its ordering. VCF Operations [handles binaries, upgrades and patches across fleet and instance components](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/lifecycle-management.html), which removes the separate Aria path. Sequencing still needs a person. The [9.1.1 release notes](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/release-notes/vmware-cloud-foundation-9-1-1-0-release-notes.html) put the fleet lifecycle component first, forbid patching VCF Operations in parallel with other components, and say not to use the Upgrade All button until every dependency is met <AsOf date="2026-11-07" />.

Licence reporting should drop to almost nothing, but only in one mode. In [automated mode, licences update every 24 hours](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/licensing/update-licenses/updatelicenses.html). Manual mode needs an update at least every 180 days, and the [disconnected route is a usage-file upload and a file download](https://blogs.vmware.com/cloud-foundation/2025/06/24/licensing-in-vmware-cloud-foundation-9-0/) on the same cycle, though the [4 Nov FAQ](https://www.vmware.com/docs/vmware-cloud-foundation-9-1-general-faqs) says APIs exist for those updates. [Late reporting ends with hosts disconnected from vCenter](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/licensing/update-licenses/updatelicenses.html), so an air-gapped site should keep this task in its figures; the [180-day note](/vcf/library/licensing/180-day-cycle/) has the dates. [Hah and Gleed's 2025 post](https://blogs.vmware.com/cloud-foundation/2025/06/24/licensing-in-vmware-cloud-foundation-9-0/) lists vDefend, Avi, Tanzu Platform and Data Services Manager as still on keys, and those stay in the count. None of this is licensing or purchasing advice, so check your entitlement with Broadcom.

Passwords save the least. VCF Operations [alerts on expiring root and admin passwords and updates them without a login to each component](https://blogs.vmware.com/cloud-foundation/2026/02/06/why-vcf-9-0-improves-it-operations-and-management/), per Peterson and Hah. Its [9.1 password page](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/fleet-management/manage-passwords.html) describes updates you run and a six-hour compliance check, with no rotation schedule, so keep the schedule you have. The [blueprint](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/fleet-management-blueprint/vcf-password-management/recommendations-for-vcf-password-management.html) says to enable SDDC Manager auto-rotation for inter-component accounts only it can manage, at the same 30, 60 or 90 days as 5.2. Broadcom's wording on that console's future isn't consistent: the [certificate recommendations](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/fleet-management-blueprint/certificate-management/recommendations-for-vcf-certificate-management.html) say 9.0 deprecates its UI, while the [rotation page](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/fleet-management/manage-passwords/using-sddc-manager-to-manage-passwords/rotate-passwords.html) still uses that UI and says deprecation comes in a future release. Check the schedule at each upgrade. The [password recommendations](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/fleet-management-blueprint/vcf-password-management/recommendations-for-vcf-password-management.html) want credentials in an enterprise vault for API or manual processes, and outbound expiry alerts need the notification plugin. Both are work someone has to own.

Findings and drift show you the work without doing it. Diagnostics [surfaces active findings, including security advisories and issues with known KBs](https://blogs.vmware.com/cloud-foundation/2026/02/06/why-vcf-9-0-improves-it-operations-and-management/), and [9.1 adds an API to feed them into ticketing](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/release-notes/vmware-cloud-foundation-9-1-0-0-release-notes/what-s-new/whats-new-vcf-ops.html). Configuration is similar. [Templates for vSphere Configuration Profile clusters monitor and schedule drift detection](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/release-notes/vmware-cloud-foundation-9-1-0-0-release-notes/what-s-new/whats-new-vcf-ops.html), [VCF Operations manages vSphere Lifecycle Manager images](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/lifecycle-management.html), and the [blueprint](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/fleet-management-blueprint.html) says current configuration capabilities focus on drift detection, so budget time to act on what they find.

## Measuring it

Vendor effort figures arrive without a baseline you can check. Dave Morera's [May post on memory tiering](https://blogs.vmware.com/cloud-foundation/2026/05/07/advanced-memory-tiering-enhancements-in-vmware-cloud-foundation-9-1/) is the pattern: 9.1 collapses set-up into a vSphere Configuration Profiles pane, creates NVMe partitions automatically and drops the host reboot, though maintenance mode remains, and he gives "over 50% reduction in configuration time" with no method. Take that as something to test.

For each recurring task, record:

1. How often it happens per year across the estate.
2. The hands-on time per occurrence, from change records or the team's estimate.
3. The number of people involved.

Annual hours are frequency × time × people. This example is constructed, so replace each number with your own: 40 certificate renewals a year at 30 minutes with two people is 40 × 0.5 × 2 = 40 hours.

Change records are the best "before" source because they already exist. If the team doesn't log hands-on time, start now and cover a few quarters, because [the SRE target is an average over a few quarters or a year](https://sre.google/sre-book/eliminating-toil/): toil is spiky. Repeat the measurement after the feature is configured, not after the upgrade, since auto-renewal saves time only once the CA integration works and [any certificate within 60 days of expiry has to be renewed by hand before auto-renewal goes on](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/fleet-management/certificate-management-9-0/set-up-automatic-renewal-of-certificates-in-vmware-cloud-foundation.html).

Record moved work as moved. The blueprint's stated principle is that [day 2 operations should run through API or workflow automation](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/fleet-management-blueprint.html), so a task someone still clicks through in VCF Operations is still manual under Rau's definition, however tidy the screen. Report what the team did with the hours as well, because time spent on automation, design or reducing incident load is the argument for the next round.

## What goes on the other side of the ledger

New work needs counting against the saving: CA configuration, depot connectivity, the fleet management components themselves, the notification plugin, [Log Management for the audit retention the blueprint recommends](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/fleet-management-blueprint/vcf-password-management/recommendations-for-vcf-password-management.html), and the [licence server appliance added in 9.1](https://www.vmware.com/docs/vmware-cloud-foundation-9-1-general-faqs), which is deployed and life-cycled automatically but has its own [9.1.1 known issue with inflated used capacity](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/release-notes/vmware-cloud-foundation-9-1-1-0-release-notes/vcfoperations-9-1-1-0-release-notes.html). Failures also still reach a person: [9.1.1 alerts when a component-managed certificate renewal fails](https://blogs.vmware.com/cloud-foundation/2026/10/14/managing-certificates-at-scale-with-vmware-cloud-foundation-9-1-1/), and someone has to fix it. If certificate replacements already fail on naming or trust problems, automation fails faster, so fix the cause first. Fewer people will remember the manual steps once the automation runs, so keep a tested manual runbook for the day it can't. The [passwords and service accounts](/vcf/library/day-2/passwords-service-accounts/) and [health checks](/vcf/library/day-2/health-checks-sos/) notes cover what those areas need.
