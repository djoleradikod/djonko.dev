<InShort>
A VCF 9 subscription is charged on **physical cores**, at least 16 per CPU, and each VCF core brings **1 TiB of raw vSAN capacity** (<KB id={313548} />). [ESX hosts are the only assets that use primary licence capacity](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/licensing/licensing-overview/licensing-model.html), so adding memory or VMs to a host adds nothing to the count <AsOf date="2026-11-07" />. Start with whichever resource is forcing your next host purchase, and book a capacity saving only when it takes a host or a drive off a quote. Staff time is another cost these levers reach, and it should be measured before anyone claims to have reduced it.
</InShort>

<Callout type="note" title="Corrected on 7 November 2026">
This note said VCF 5.x moved to per-core licensing in a 2024 change, that 5.x estates could hold per-CPU keys, and that vSAN entitlement pools across vCenters. Lenovo's VCF 5 table shows per-core with a per-CPU minimum, and Broadcom's licensing overview says the default licence pools capacity by product and Site ID. The note's ranking of cost lines by size and its claim that VCF 9 moves "most" lifecycle work into fleet management had no source, so both are gone.
</Callout>

## The cost lines and what moves them

These lines aren't ranked by size, because that split depends on your hardware, staff and contract. Measure it before choosing where to start.

| Cost | What drives it | Lever | Covered in |
|---|---|---|---|
| Core subscription | Physical cores, with the 16-per-CPU floor | CPU choice, consolidation, fewer hosts | [Counting cores](/vcf/library/value/core-counting-and-cpu-choice/), [consolidation](/vcf/library/value/consolidation-and-headroom/) |
| Management hosts | Licensed cores on hosts that run only management | A consolidated design, where the availability target allows it | [Minimal footprint blueprint](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/vcf-fleet-in-a-single-site-with-minimal-footprint-blueprint.html), read as a lever in the analysis below |
| vSAN add-on capacity | Raw TiB above the entitlement | Protection scheme, compression, deduplication | [vSAN entitlement](/vcf/library/value/vsan-entitlement/), [space efficiency](/vcf/library/value/vsan-esa-space-efficiency/) |
| Memory hardware | DRAM per host | NVMe memory tiering | [Memory tiering](/vcf/library/value/nvme-memory-tiering/) |
| Wasted allocation | Oversized and idle VMs holding capacity | Right-sizing and reclamation | [Right-sizing](/vcf/library/value/rightsizing-with-vcf-operations/), [reclamation](/vcf/library/value/reclaiming-idle-capacity/) |
| Separate tools | Monitoring, logging and self-service bought outside VCF | Use what the licence includes | [What VCF includes](/vcf/library/value/using-what-vcf-includes/) |
| Administration hours | Manual lifecycle, certificates, passwords | Central handling in VCF Operations, with auto-renewal limited by your CA | [Admin effort](/vcf/library/value/cutting-admin-effort/) |

## Fewer hosts is what reaches the bill

Hosts are what consume the licence, so a saving inside an existing cluster has no licence value until it changes a purchase. Reclaiming 200 GB of memory from idle VMs moves no invoice line on its own. Record it against the next growth request or hardware refresh, where it can become a host you don't buy. This holds for every capacity lever below, and it is why a cost case should name the purchase each of those savings displaces.

A cluster is sized by whichever resource runs out first. Where that is memory, cores are being bought to carry DIMMs, and NVMe tiering is a direct answer, with conditions to check first. Broadcom's guidance asks for [active memory between 0% and 50% of DRAM before tiering](https://techdocs.broadcom.com/us/en/vmware-cis/vsphere/vsphere/9-1/vsphere-resource-management/memory-tiering-over-nvme/memory-tiering-considerations-and-best-practices.html), no memory overcommit, and NVMe devices not shared with vSAN. Check active memory first, because a host above that limit falls outside the guidance, and price the drives, because they are new hardware on the other side of the sum. Morera's ["up to 40% lower TCO"](https://blogs.vmware.com/cloud-foundation/2026/05/07/advanced-memory-tiering-enhancements-in-vmware-cloud-foundation-9-1/) comes with no calculation in that post, so don't carry it into a business case.

Where raw disk runs out first, the licence follows [raw TiB contributed to vSAN clusters](https://knowledge.broadcom.com/external/article/313548/counting-cores-for-vmware-cloud-foundati.html), and data reduction only helps if it means installing fewer drives. In 9.1 [compression is always on and global deduplication is an optional extra](https://www.vmware.com/docs/vmw-vsan-space-efficiency), so deduplication is the choice to size. Before buying add-on TiB, check Site IDs too. The [default licence pools subscriptions for the same product in the same Site ID](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/licensing/licensing-overview.html). Surplus under one Site ID wouldn't cover a shortfall under another, which is an inference from that definition.

Where CPU runs out first, the [16-core floor and the host count interact](/vcf/library/value/core-counting-and-cpu-choice/). That note runs the sum, and it also weighs the 72-core order minimum, which Lenovo's table lists and that note doesn't find in Broadcom's own documents. Right-sizing and reclamation sit underneath all three cases. [Reclamation deletes idle VMs, old snapshots and orphaned disks, while rightsizing changes a VM's allocation](https://blogs.vmware.com/cloud-foundation/2025/08/12/vmware-cloud-foundation-helps-you-optimally-size-vms-and-keep-your-infrastructure-and-workloads-running-smoothly/). VMware's post describes the first as the capacity tool and the second as the performance one. [This site's cost method](/vcf/library/value/building-the-cost-case/) starts with reclamation, so that right-sizing doesn't count memory an idle VM is about to give back.

<Callout type="analysis" title="Management hosts are licensed cores too">
Broadcom's [minimal footprint blueprint](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/vcf-fleet-in-a-single-site-with-minimal-footprint-blueprint.html) puts all management and workload components in a single vSphere cluster. It presents that as a design profile and gives no saving. Reading it as a cost lever is this site's analysis: every ESX host consumes cores, so hosts that run only management are a line worth questioning. The price is availability, since the design tolerates one host failure and sits in one rack and one availability zone. Take that trade only if the workloads can live with it, and let the availability requirement decide before the licence sum does.
</Callout>

## What the included tools cover

VCF 9 licensing [covers vCenter and ESX, vSAN, NSX, HCX, VCF Operations, VCF Automation, VKS and VCF Private AI Services](https://www.vmware.com/docs/vmware-cloud-foundation-9-1-general-faqs). Avi Load Balancer, vDefend Firewall and VMware Live Recovery stay separately licensed, and the same FAQ lists vSAN add-on capacity among the separately bought services <AsOf date="2026-11-07" />. A tool you already pay for elsewhere only comes off the budget when one of the included components replaces it and the old contract ends, so compare against your renewal dates.

## Where administration time goes

Vivek Rau's chapter in the Google SRE book defines [toil](https://sre.google/sre-book/eliminating-toil/) as manual, repetitive, automatable and tactical work with no enduring value, which scales linearly as a service grows. Certificate replacement, per-component patching and licence key management fit that definition in 5.x, and so does password rotation where SDDC Manager's schedule doesn't cover the account. VCF 9 changes how each is done. [VCF Operations centralises certificate and password handling](https://blogs.vmware.com/cloud-foundation/2026/02/06/why-vcf-9-0-improves-it-operations-and-management/), with auto-renewal through a certificate authority, expiry alerts on root and admin accounts, password updates without logging in to each target, and lifecycle work on one screen. That account comes from Peterson and Hah on VMware's own blog, so treat it as what to test. Separately, [a single licence file replaces per-component keys](https://blogs.vmware.com/cloud-foundation/2025/06/24/licensing-in-vmware-cloud-foundation-9-0/) for core VCF, while separately purchased add-ons keep their own licensing.

Two limits can keep the saving smaller than the feature list suggests. The fleet management blueprint names [automated lifecycle management as an objective, but says current configuration management capabilities focus on drift detection](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/fleet-management-blueprint.html), so budget someone's time to act on what it finds. And licensing adds a new recurring job: [usage reports at least every 180 days](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/licensing/licensing-overview.html), sent automatically in connected mode and uploaded by hand in disconnected mode. The [admin effort note](/vcf/library/value/cutting-admin-effort/) lists what changed and how to measure the hours it gives back.

## How to use this section

Start with [building the cost case](/vcf/library/value/building-the-cost-case/) if you need to justify a change to someone else: state the baseline from measured data, write each assumption down, and show the pessimistic result first, then the expected one. For a vendor's percentage, the [cost claims ledger](/vcf/library/value/cost-claims-ledger/) shows who paid for each public figure and what it leaves out. The worked examples in these notes are constructed to show the arithmetic, and none of them describes a real customer.

<Callout type="note" title="Prices">
These notes don't quote Broadcom list prices, because per-core prices vary by contract, term, region and partner, and they change. The examples count cores and TiB, which convert to money once you apply your own quote. Nothing here is legal or purchasing advice, so check your order documents and [Broadcom's licensing documentation](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/licensing/licensing-overview.html) before acting on it.
</Callout>
