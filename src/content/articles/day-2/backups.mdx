<InShort>
In 5.x, SDDC Manager backed itself up to SFTP and configured NSX backups. vCenter used its own file-based backup, and Aria products were backed up separately. In 9.x, backup configuration lives in VCF Operations at two levels. **Fleet-level** settings cover management components: VCF Operations, VCF Automation, the identity broker and, in 9.1, the management services runtime. **Instance-level** settings cover SDDC Manager and the domains. In 9.1, fleet lifecycle schedules the management component backups per instance to SFTP, with a host key thumbprint and an encryption passphrase. The services runtime is new, important, and easy to forget.
</InShort>

## What to back up, and how

| Component | Method |
|---|---|
| SDDC Manager | SFTP file-based backup, configured per instance |
| NSX Manager | Configured through SDDC Manager. Mind the retention-setting issue in <KB id={442696} />. |
| vCenter | Native file-based backup from the VAMI |
| VCF Operations | SFTP through fleet lifecycle, plus image-based backup |
| Services runtime and management services (9.1) | Fleet lifecycle schedule, per instance, to SFTP |
| VCF Automation, identity broker | Fleet-level backup settings |

## Rules that silently break backups

- **SFTP user in UPN form.** `user@domain`, not `domain\user`. The backslash breaks the job, and in 9.1 it fails the fleet lifecycle upgrade too (<KB id={450561} />).
- **Standard SFTP port.** Non-standard ports have failed host key validation in 9.1.
- **Frequency.** Fifteen-minute incrementals look safe, but they queue other lifecycle tasks such as VCF Automation prechecks. Every four hours is a better default during change windows (<KB id={456790} />).
- **Locks.** A hung backup can leave a lock that blocks password remediation and host operations (<KB id={439473} />, <KB id={447314} />).

## Restores need practice

A backup no one has restored is a hope, not a control. Two restores are worth practising in a lab:

- **SDDC Manager** from SFTP onto a fresh appliance.
- **9.1 log management** onto a rebuilt runtime, which needs a documented post-restore step to resume ingestion (<KB id={436904} />).

Before upgrades, VCF Operations has its own snapshot ritual: take the cluster offline, snapshot every node, bring it online, then upgrade (<KB id={450430} />).

<Callout type="field">
Add "last successful backup per component" to the weekly operations report, as one line per component with a date. A recovery starts from that date.
</Callout>

## Pitfalls

- **Backing up the old list.** The 9.1 services runtime holds fleet lifecycle, the depot and, possibly, the identity broker. Confirm it appears in the backup configuration and that a recent backup exists.
- **Losing the passphrase.** Encrypted backups without the passphrase are useless. Store it in the vault with an owner.
- **Using snapshots as backups.** They aren't.
