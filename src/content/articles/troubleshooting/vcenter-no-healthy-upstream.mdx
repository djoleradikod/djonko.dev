<InShort>
The vSphere Client sits behind a proxy (Envoy). "No healthy upstream" means the services behind it aren't responding. Find out which, then why. Work in this order: **check partitions** (`df -h`, especially `/storage/log` and `/storage/seat`), **check certificates** (the VECS expiry loop), **check services** (`service-control --status --all`), then read the log of the first service that failed. Rebooting again won't clear an expired certificate or a full disk.
</InShort>

## The first five minutes

```bash
# 1. Disk
df -h | grep -E 'storage|/$'

# 2. Services: which ones are stopped?
service-control --status --all

# 3. Certificates: anything expired? (loop from KB 344201)
for store in $(/usr/lib/vmware-vmafd/bin/vecs-cli store list | grep -v TRUSTED_ROOT_CRLS); do
  echo "[*] $store"; /usr/lib/vmware-vmafd/bin/vecs-cli entry list --store $store --text | grep -ie "Alias" -ie "Not After"
done

# 4. Time
date -u
```

The VCF Diagnostic Tool for vCenter runs a broader set of checks in one go (<KB id={344917} />).

## Cause by cause

| Finding | Fix |
|---|---|
| A certificate past "Not After" | Snapshot, then vCert to check and replace, then restart all services (<KB id={344201} />, <KB id={385107} />) |
| STS signing expired on 9.0.1, SSH refused | Unmask and start sshd, then vCert STS replacement (<KB id={427237} />) |
| `/storage/log` full from `/storage/log/vmware/esx/` | Hosts are sending syslog to vCenter. Remove the target from the hosts, clear the folder, start services (<KB id={434671} />). An unrotated `vmon` log is another known cause (<KB id={399535} />). |
| `/storage/seat` full | Event and task tables bloated. Purge or grow the disk as the KB describes, with no snapshot on the disk you grow (<KB id={410118} />) |
| vpxd crashes with "Excessive depth in document" | A VM with hundreds of snapshots in its chain. Identify it, consolidate on the host, start vpxd (<KB id={453758} />) |

<Callout type="field">
Add vCenter certificate expiry and partition usage to the same monthly report as backups, so you see an expiring certificate or a filling partition before a user sees "no healthy upstream".
</Callout>

## Pitfalls

- **Rebooting repeatedly.** If a certificate expired or a disk is full, the reboot ends in the same place.
- **Snapshots on linked vCenters.** Use the cold-snapshot approach the KBs describe before certificate work.
- **Deleting logs that explain the outage.** Copy them off first if a root cause analysis will be needed.
