<InShort>
In VCF 5.x you consumed NSX mostly through its own manager UI, and SDDC Manager deployed edge clusters. In 9.x the everyday networking tasks happen in vCenter: VPCs, subnets, network connectivity and edge deployment. Two connectivity models exist. **Centralized** routes through a transit gateway to a Tier-0 on edge VMs. **Distributed** maps the transit gateway onto a VLAN shared by every host, with no edge VMs at all. Several older options are gone: multiple NSX instances per vCenter, standalone NSX lifecycle, N-VDS on hosts, and the NSX load balancer, which Avi replaces.
</InShort>

**Centralized** is the right default when you need stateful services such as NAT, gateway firewall or load balancing in front of VPCs. It is also required for vSphere Supervisor and VCF Automation, which need edges in active/standby with a centralized connectivity gateway. Edges can now be deployed through a guided workflow in vCenter.

**Distributed** suits simple, high-throughput east-west and north-south designs where every host can reach one shared VLAN. It supports only distributed services. For example, it supports stateless 1:1 NAT and distributed DHCP, but not DHCP relay. Check the current feature matrix before promising anything stateful.

## What to check before an upgrade from 5.x

- **Multi-NSX.** If any vCenter is attached to more than one NSX Manager, untangle it before the upgrade. 9.x supports one NSX per vCenter.
- **N-VDS on hosts.** Migrate any host still on N-VDS to VDS first. Edges can stay on N-VDS.
- **Load balancer use.** Find every NSX load balancer and plan the move to Avi. Version alignment matters in the 9.1 upgrade too: the upgrade sequence calls out an Avi target and a default NSX distributed load balancer attached to a group (<KB id={440901} />).
- **Unsupported attachments.** Bare-metal NSX agents, KVM transport nodes and third-party OpenStack integrations do not carry forward.
- **Import prerequisites.** Workload domains imported into 9.x need NSX 4.1.0.2 or later. Clusters without NSX get it deployed during import.

## Pitfalls

- **Treating vCenter networking as a toy.** It is the supported Day-2 path in 9.x, and VCF Automation expects VPCs. Learn it before a network team asks about it.
- **Choosing distributed connectivity, then needing NAT.** Moving from distributed to centralized later means redesigning the north-south path. Ask about stateful services in the first workshop.
- **NSX SSO.** NSX consumes VCF SSO in 9.x. If the embedded broker integration fails, NSX logins fail with it (<KB id={432503} />).
