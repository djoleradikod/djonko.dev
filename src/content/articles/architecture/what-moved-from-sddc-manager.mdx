<InShort>
In 5.x, SDDC Manager was both the console and the engine. In 9.0 it keeps the engine role for core infrastructure: ESX, vCenter, NSX and workload domains. Most of its screens moved to VCF Operations, and some moved to vCenter. In 9.1 its UI is formally deprecated and the new SDDC lifecycle service drives it through a service account. The practical consequence is simple: you rarely log in to SDDC Manager, but it still has to be healthy, or core lifecycle stops.
</InShort>

## What SDDC Manager still does

**Core lifecycle.** SDDC Manager plans and runs upgrades and patches for ESX, vCenter and NSX in its instance. In 9.1 it also handles HCX lifecycle, workload domain deployment and import, and stretched vSAN clusters. Its service accounts on vCenter, NSX and ESX are what make that possible. They are the `svc-sddc-manager-…` and `svc-vcf-…` accounts in the accounts table in TechDocs.

**Instance inventory.** VCF Operations reads the instance through the VCF adapter on a cloud proxy, which calls the SDDC Manager API. If SDDC Manager is down, the SDDC Manager page in VCF Operations goes blank and the adapter reports a collection failure (<KB id={443680} />).

**Execution back end in 9.1.** The 9.1 SDDC lifecycle service holds an administrator account on SDDC Manager. It is created as `svc-vcf-sddc-lcm-SDDC_MANAGER-<uuid>` and rotated every 30 days. Lifecycle requests that start in VCF Operations pass through SDDC lifecycle and arrive at SDDC Manager as API calls. If that account is changed or deleted out of band, upgrades and inventory sync fail. Repeated failed logins can also lock the runtime nodes out of SDDC Manager (<KB id={450375} />).

The VCF blog's Day-2 comparison is the best single list of where each task went. The short version:

- **To VCF Operations:** workload domain deployment, backup configuration, DNS and NTP settings per instance, certificate authority configuration, certificate management (now with auto-renewal) and [password management](/vcf/library/day-2/passwords-service-accounts/), where Update runs while Rotate stays in SDDC Manager.
- **To vCenter:** network pools, host commissioning and decommissioning, cluster creation and expansion, and NSX edge cluster deployment. For workload domains these need VCF SSO and vCenter linking in place first.
- **To fleet lifecycle:** everything Aria Suite Lifecycle did for the management components. That is a separate appliance in 9.0 and a service in 9.1. See <a href="/vcf/library/architecture/aria-lifecycle-to-services-runtime/">From Aria Suite Lifecycle to the services runtime</a>.

## The password and certificate overlap in 9.0

9.0 is a transition release, and the split is not perfectly clean. In 9.0, automatic rotation for the management components is not complete (<KB id={426872} />). SDDC Manager password management stays the authoritative source for core component accounts (<KB id={435599} />). In 9.1, VCF Operations owns more of it. From 9.1.1 even SDDC Manager's own `vcf`, `root` and `admin@local` passwords can be managed from the VCF Operations UI or API, where 9.1 still required changing `root` and `vcf` in the OS and `admin@local` through the SDDC Manager API ([accounts table](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/fleet-management/manage-passwords/accounts-in-vmware-cloud-foundation.html), [9.1.1.0 release notes](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/release-notes/vmware-cloud-foundation-9-1-1-0-release-notes/vcfoperations-9-1-1-0-release-notes.html)).

<Callout type="warn" title="Don't hand service accounts to a PAM tool">
TechDocs is explicit: VCF service accounts must not be rotated or managed by an external privileged access management tool. Rotation has to go through VCF Operations or SDDC Manager, or the components fall out of sync with each other.
</Callout>

## Pitfalls

- **Ignoring SDDC Manager because "it's deprecated".** Only the UI is deprecated. Disk space, its services and its certificates still matter, and a failed SDDC Manager stops core upgrades.
- **Doing Day-2 tasks the old way.** Commissioning hosts or rotating passwords through old SDDC Manager API scripts can still work in places, but it bypasses the 9.x workflows and can leave VCF Operations out of step. Update automation to the 9.x paths.
- **Looking for SDDC Manager in SSO.** It is not in VCF SSO. Keep its local admin credentials somewhere safe.
