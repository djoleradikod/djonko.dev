<InShort>
Plan for workloads to keep running when a VCF management component fails, and for lost control: lifecycle, configuration, monitoring or sign-on, depending on the component. We found no outage matrix from Broadcom <AsOf date="2026-11-07" />, so that expectation is an inference from where the components sit. Licensing is the documented exception. In 9.1, if a 90-day evaluation ends before license sync returns, hosts go Disconnected and VMs can't power on (<KB id={443240} />), and licenses [expire after the 180-day update period](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/licensing/license-server-overview/license-server-downtime-impact.html). Each row below separates the documented effect from the inferred one. Test the inferred column on non-production before it goes in a runbook.
</InShort>

<Callout type="note" title="Corrected on 7 November 2026">
This note used to say workloads survive the loss of any component, that log ingestion continues in 9.1 while VCF Operations is down, and that lifecycle, depot and backups stopping with the services runtime was documented. We found none of those documented as outage behaviour, the NSX exclusion-list row had no source, and several KB-cited rows described narrower faults, such as the blank SDDC Manager page in <KB id={443680} />, so those faults now have their own table.
</Callout>

## The choices that set the blast radius

**Run the services runtime in the HA model.** In the Simple model, [losing the single control plane node means redeploying the cluster and restoring from backup](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/vmware-cloud-foundation-concepts/vcf-management-services-models.html), and that page positions Simple for testing and proof of concept. The [single-site blueprint](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/vcf-fleet-in-a-single-site-blueprint.html) selects HA. The choice carries most of the matrix, because the runtime [hosts](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/deployment/vcf-management-appliances.html) fleet lifecycle, SDDC lifecycle, the software depot, the instance-mode identity broker, log management, real-time metrics and telemetry.

**Decide how many instances a broker failure may lock out.** [A fleet-wide broker outage "impacts the VCF fleet"](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-library/single-sign-on-models/vcf-fleet-wide-sso-model.html). With [one broker per instance](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-library/single-sign-on-models/single-single-sign-on-deployment-per-vcf-instance.html) it only affects logins for that instance, at the price of more resources and repeated sign-in between instances. [Local accounts and the emergency API client keep working](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-library/single-sign-on-models.html) across that page's broker failure scenarios, so keep those credentials reachable. For placement, [the instance model is the recommendation for production](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/vmware-cloud-foundation-concepts/auth-design-vcf.html), while the [9.0 page](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-0/fleet-management/what-is/deployment-models-for-sso.html) warns that embedded mode can be a single point of failure if the management domain vCenter goes down.

<Callout type="analysis" title="The blueprints accept the large blast radius">
The [single-site](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/vcf-fleet-in-a-single-site-blueprint.html) and [single-region](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/vcf-fleet-with-multiple-sites-in-a-single-region-blueprint.html) blueprints both select one fleet-wide broker and list "Tolerates failure of a single management component". Those fit together only if tolerating means the platform keeps running while fleet-wide sign-on is down, and neither blueprint spells that out. Follow the blueprint when local-account access is acceptable for the length of a restore. If it isn't, price a cross-instance or per-instance design.
</Callout>

**Alert on the license server, and write down its recovery.** Its outage causes [no immediate problem for workloads or management tasks](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/licensing/license-server-overview/license-server-downtime-impact.html), so the danger is an outage nobody notices while the clocks run. Alert on the vSphere message in <KB id={443240} /> and confirm vSphere HA on its cluster. [Backup isn't required](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/vcf-fleet-in-a-single-site-blueprint/management-domain-design-selections%281%29/operations-layer-fleet-single-site/vcf-fleet-in-a-single-site-simple-license-server-model.html): deploy a new instance and migrate the licenses within 90 days. [The license server note](/vcf/library/licensing/license-server/) has the detail. Licensing rows here apply to 9.1 only, since the server and the KB are both 9.1.

**Add the second cloud proxy.** Deployment gives you one, and the [blueprint adds another in a collector group](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/vcf-fleet-in-a-single-site-blueprint.html). With a group, sources move to another proxy once VCF Operations detects the failure, though [logs may be lost during the failover](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-library/vcf-operations-design/vcf-operations-for-logs-deployment-models.html).

**Map the first instance separately.** [Fleet lifecycle always, and the depot and broker unless you add others, sit in the first instance](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/deployment/vcf-management-appliances.html), so losing that management domain takes them from every instance. That's an inference from placement, and it gives the first instance's management domain a stronger claim on recovery planning than any other. [VCF Operations is also one per fleet](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/troubleshooting-guide/environment.html).

Licensing, monitoring and logins carry on. |
| **SDDC Manager** | [One per instance](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-library/vcf-operations-design/sddc-manager-design.html) | [Supplies VCF Operations with](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/deployment/vcf-management-appliances.html) lifecycle for ESX, vCenter, HCX and NSX, workload domain deployment and import, and vSAN stretched cluster configuration. [Not covered by the broker](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/vmware-cloud-foundation-concepts/auth-design-vcf.html). | Those functions and VCF adapter collection stop for that instance. Other instances carry on. Licensing is unaffected. |
| **Cloud proxy** | [One by default in each instance](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-library/vcf-operations-design/vcf-operations-for-logs-deployment-models.html) | HAProxy services that stop responding leave the proxy Offline and the SSO configuration page failing to load (<KB id={437258} />, 9.x). Licensing is probably degraded. Logins continue. |
| **Identity broker** | [Instance mode on the runtime, or embedded in vCenter](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/vmware-cloud-foundation-concepts/auth-design-vcf.html) | Outage impacts [the whole fleet](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-library/single-sign-on-models/vcf-fleet-wide-sso-model.html) or [all components in the instance](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-library/single-sign-on-models/single-single-sign-on-deployment-per-vcf-instance.html), by SSO model. [Local accounts and the emergency API client keep working](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-library/single-sign-on-models.html). | Lifecycle, licensing and monitoring carry on. |
| **Software depot (9.1)** | [Runtime, first instance, optionally others](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/deployment/vcf-management-appliances.html) | [Handles binaries for all VCF components](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/lifecycle-management.html). | No new binaries, so upgrades that need them wait. | **Log management (9.1)** | [Runtime worker nodes](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-library/vcf-operations-design/vcf-operations-for-logs-deployment-models.html) | [HA recommended, Simple for test and dev only; plan N+1 or N+2 replicas](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-library/vcf-operations-design/vcf-operations-for-logs-deployment-models.html). ## Infrastructure and dependencies

| Failure | Documented effect | Inferred, so test first |
|---|---|---|
| **Management domain vCenter** | vSphere HA is the supported availability model, and vCenter HA isn't supported (<KB id={441793} />). Embedded broker [can be a single point of failure](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-0/fleet-management/what-is/deployment-models-for-sso.html) (9.0). | Sign-on lost if the broker is embedded. vCenter-dependent operations stop for what it manages. |
| **NSX Manager** | While HA restarts managers at a second site in a 9.0 multisite design, about ten minutes, [the management plane is unavailable and the data plane isn't impacted](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-0/advanced-network-management/administration-guide/managing-nsx-t-in-multiple-locations/nsx-t-multisite.html). | The same holds for other manager outages. Broadcom states it for this scenario, so confirm yours. NSX sign-on through SSO is lost too. |
| **DNS** | All VCF and VVF deployments require A and PTR records (<KB id={460245} />), and [runtime and broker FQDNs need entries before deployment](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/vcf-fleet-in-a-single-site-with-minimal-footprint-blueprint/management-domain-design-selections/operations-layer/vcf-management-services-in-the-first-vcf-instance-model-minimal-fleet.html). License server records missing: server shows "Not configured", assignments fail (<KB id={445428} />, <KB id={453197} />, <KB id={440630} />). Cloud proxy HAProxy needs every node's FQDN to resolve before it starts (<KB id={437258} />). | Upgrades and bootstrap that need these records fail. A wider DNS loss compounds across the rows above. |

## Faults that look like outages

In these rows a KB or release note gives a narrower cause than component failure, so check them before declaring an outage.

| Symptom | Documented cause | Scope |
|---|---|---|
| SDDC Manager page blank in VCF Operations, VCF adapter Failed, proxy collection stopped | Communication timeout between the adapter and SDDC Manager services (<KB id={443680} />) | 9.0.x |
| Upgrade fails at `vmsp_upgrade` or `post_upgrade_inventory_sync`, `CLIENT_IP_BLOCKED` on runtime nodes | On VCF, rotations delete the SDDC lifecycle service accounts, and repeated 401s lock the nodes out of SDDC Manager (<KB id={450375} />) | VCF and VVF |
| Custom role push shows "Salt infrastructure is down" | Salt services not responding, so restart Salt RaaS and Salt master (<KB id={453736} />) | 9.1.0.0 |
| Management Services "Not configured"; password policy or fleet DNS tasks may fail for that site | Management services adapter not registered, because it was offline when added, so retry the configure task (<KB id={455296} />) | 9.1 |
| Log Management installed but Operate > Logs offers to install it; its backup fails | Intermediate CA missing from `platform-trust` after using the automated Microsoft CA URL (<KB id={441515} />) | 9.1.x |
| Depot stays "Disconnected" while validation succeeds | Firewall blocks Broadcom URLs, and the depot now runs on the runtime's IP pool (<KB id={443216} />) | 9.1.0 |
| Upgrade fails with `VCFMS-HEALTH-002` | Runtime VMs' cluster, resource pool or network changed (<KB id={452124} />). [Moving them to another pool or folder also breaks later Day-N work](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/release-notes/vmware-cloud-foundation-9-1-1-0-release-notes/vcfoperations-9-1-1-0-release-notes.html). | 9.1 |

## Restart order for the runbook

Bring up [the management domain first, then workload domains and workloads](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/fleet-management/vcf-shutdown-and-startup/sddc-startup.html). For the runtime on 9.1.0.x after a graceful shutdown, power on control plane VMs, wait five minutes, power on workers and allow 15 to 20 minutes before manual recovery (<KB id={440862} />). The [9.1.1.0 notes](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/release-notes/vmware-cloud-foundation-9-1-1-0-release-notes/vcfoperations-9-1-1-0-release-notes.html) list the failure to recover automatically as resolved, so the manual steps should be rarer after patching. Don't force power-off while a graceful shutdown runs (<KB id={440874} />).
