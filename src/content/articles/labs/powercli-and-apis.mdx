<InShort>
**VCF PowerCLI** is the renamed continuation of VMware PowerCLI: existing cmdlets, modules and scripts keep working. Install it from the PowerShell Gallery as `VCF.PowerCLI`. For VCF-specific work, the **SDDC Manager API** still covers domains, clusters, hosts, tasks and credentials, and the **VCF Operations API** covers alerts, inventory, and in 9.x much of fleet management. Start every automation project with **read-only** calls: list domains, failed tasks and active alerts. Write operations come later, behind a change process.
</InShort>

## Where to automate what

| Task | Best API or tool |
|---|---|
| Domains, clusters, hosts, network pools, failed tasks | SDDC Manager API |
| Alerts, inventory, reports, health | VCF Operations API |
| VMs, hosts, storage, vSphere configuration | vCenter, through PowerCLI |
| Segments, gateways, firewall | NSX API, or the NSX Terraform provider |
| Repeatable infrastructure | Terraform. See [Terraform for VCF](/vcf/library/labs/terraform-for-vcf/). |

## A safe first script

```powershell
# Install once
Install-Module VCF.PowerCLI -Scope CurrentUser

# Read-only: list domains and failed tasks from SDDC Manager
$sddc = "sddc-manager.rainpole.io"
$cred = Get-Credential
$body = @{ username = $cred.UserName; password = $cred.GetNetworkCredential().Password } | ConvertTo-Json
$tok  = (Invoke-RestMethod -Method Post -Uri "https://$sddc/v1/tokens" -Body $body -ContentType "application/json" -SkipCertificateCheck).accessToken
$h    = @{ Authorization = "Bearer $tok" }

(Invoke-RestMethod -Uri "https://$sddc/v1/domains" -Headers $h -SkipCertificateCheck).elements |
  Select-Object name, type, status

(Invoke-RestMethod -Uri "https://$sddc/v1/tasks" -Headers $h -SkipCertificateCheck).elements |
  Where-Object status -eq "FAILED" | Select-Object name, creationTimestamp, id
```

`-SkipCertificateCheck` is for labs. In production, trust the CA instead. PowerCLI also includes SDK-generated cmdlets for the VCF APIs. Run `Get-Command -Module *Vcf*` to see what your version provides.

<Callout type="field">
Give every automation a read-only mode and run it in that mode for a week before allowing changes. It finds the edge cases (an unexpected domain, an old task, a missing permission) without changing anything.
</Callout>

## Pitfalls

- **Using personal administrator accounts** for automation. Create a dedicated account with the least role needed.
- **Hard-coding passwords** in scripts. Use a vault or the PowerShell SecretManagement module.
- **Assuming 5.x endpoints still behave the same** in 9.x. Check the API reference for your version; some operations were deprecated.
