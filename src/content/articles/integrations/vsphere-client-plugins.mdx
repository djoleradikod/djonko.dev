<InShort>
A remote plugin is a vCenter **extension**: a key, a download URL and a **thumbprint**. The vSphere Client downloads the package and checks the thumbprint before deploying it. So a plugin breaks when the URL is unreachable, the certificate changed, or the product that registered it is gone. Local plugins are no longer supported in 9.x. The VCF Operations plugin **does not upgrade** with VCF Operations or vCenter; it updates only when the VCF Operations certificate is renewed (<KB id={427228} />). The fix is usually to re-register from the owning product, after removing stale extensions with the MOB if needed.
</InShort>

## Failures and fixes

| Message | Cause and fix |
|---|---|
| "Error downloading plug-in. Make sure that the URL is reachable and the registered thumbprint is correct." | No 443 path between vCenter and the plugin source, or a deprecated plugin. Fix reachability or remove it (<KB id={411268} />). |
| VCF Operations plugin shows "no healthy upstream" | VCF Operations was deleted without unregistering. Redeploy and re-add the vCenter with plugin management to overwrite the registration (<KB id={433208} />). |
| SDDC Manager plugin fails after an out-of-band vCenter certificate change | Trust and thumbprint. Sync trust or redeploy the plugin from SDDC Manager (<KB id={419087} />). |
| vSAN plugins "DOWNLOAD_FAILED ... No issuer certificate" | A stale thumbprint in vCenter's extension table. Fix as the KB describes, with a snapshot (<KB id={432196} />). |
| "Plugin configuration with Reverse Proxy failed" | The vSphere Client service account role lacks Global.Proxy (<KB id={312247} />). |
| Live Recovery plugin undeploys after about 30 minutes | A stale cached package from an older version (<KB id={417767} />). |
| Plugin stuck at an old version | A cached package. Clear the client cache folder and restart the UI service (<KB id={395813} />). |

## Clean re-registration

1. **Snapshot vCenter.** For linked vCenters, offline snapshots of all nodes.
2. Open `https://<vcenter>/mob`, then **content > ExtensionManager**. Use **FindExtension** to confirm the key.
3. **UnregisterExtension** for the stale key (<KB id={426913} />).
4. Remove the cached package under `/etc/vmware/vsphere-ui/cm-service-packages/`.
5. `service-control --restart vsphere-ui`.
6. **Re-register from the owning product**: the VCF Operations account's Manage Integrations, the NSX compute manager edit, or SDDC Manager's UI service.

Logs: `/var/log/vmware/vsphere-ui/logs/vsphere_client_virgo.log` (search for DOWNLOAD_FAILED and DEPLOYMENT_FAILED) and the reverse proxy log.

<Callout type="field">
Add "re-check Client Plugins" to every certificate replacement runbook. A certificate change can break plugins, because they are verified by thumbprint, and the check is quick.
</Callout>

## Pitfalls

- **Expecting the VCF Operations plugin to update** after an upgrade.
- **Unregistering a live extension** that another product still needs. Confirm the key first.
- **Two NSX plugins** on one vCenter are expected with Federation. Don't remove one as a duplicate.
