<InShort>
Build > Lifecycle in VCF Operations is assembled from **plugins**: the SDDC Manager plugin for VCF Instances, and the fleet lifecycle plugin for VCF Management. VCF Operations proxies them, so a failure appears as "Service or view is not available" with the real error in **`web-vcf.log`** on VCF Operations. The usual causes: TCP 443 blocked between SDDC Manager or the runtime and every VCF Operations node (<KB id={435258} />), a duplicate trusted certificate after the 9.1 upgrade (<KB id={448522} />), an expired internal certificate in 9.1.0 (<KB id={448618} />), or no fleet lifecycle entry in the **service registry** (<KB id={444151} />).
</InShort>

## Diagnosis

1. **Browser first.** Try a private window. A stale cache after the 9.1 upgrade causes endless spinners (<KB id={441205} />).
2. **Read `web-vcf.log`** on VCF Operations (`/storage/log/vcops/log/`). "Connect timed out" on a `plug/sddc-...` path means reachability (<KB id={435258} />). A failed manifest download points at trusted certificates (<KB id={448522} />).
3. **Check the registry.** `https://<ops-fqdn>/casa/services` should list an entry of type `VCF_FLEET_LCM`. If it doesn't, there are no Lifecycle components and no Upgrade tab. That is a support case (<KB id={444151} />).
4. **Check the serving side.** "TLS_error ... CERTIFICATE_VERIFY_FAILED" in 9.1.0 is an internal certificate that didn't reload after rotation (<KB id={448618} />). "Identity Broker is not reachable" can be an IP conflict with a stale VM (<KB id={454179} />).

## Fleet Management says "Get started" when it's deployed

The page needs four things at once: management services running, Salt RaaS and Salt master running, the VCF adapter **Collecting**, and the management vCenter on 9.1.0 or later (<KB id={443327} />). A component that shows "Powered Off" with no actions after the upgrade is a stale hostname in the lifecycle database (<KB id={449937} />).

<Callout type="field">
For any Lifecycle UI ticket, ask for a HAR file from the browser and `web-vcf.log` at the same time. Together they show which plugin failed and why, which is usually the whole diagnosis.
</Callout>

## Pitfalls

- **Restarting VCF Operations** for a plugin that is failing on the other side.
- **Opening firewalls to one VCF Operations node.** Plugins are fetched by every node.
- **Editing the registry file by hand.** It is a support-only change.
