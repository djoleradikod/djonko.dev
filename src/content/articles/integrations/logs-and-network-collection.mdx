<InShort>
**Log collection** uses its own system-managed vCenter account per source, named like `svc-li-vc-...@vsphere.local`, with a number that increments on each rotation (<KB id={432694} />). With a VCF licence, the integration between VCF Operations and the logs cluster is configured automatically when the logs cluster is imported; with VVF it is a manual tile (<KB id={425906} />). In 9.1, vCenter ships its own log agent, and upgrading vCenter **wipes the old log configuration**, so re-enable collection afterwards (<KB id={433089} />). **Network and flow collection** fails if NSX was previously added to VCF Operations for networks by IP: remove it, wait two hours, re-add by FQDN (<KB id={448643} />).
</InShort>

## Log collection failures

| Symptom | Cause and fix |
|---|---|
| VC collection status "Error: Failed to login" | Credential rotation pending or failed. Rotate the integration's credential (<KB id={432694} />). |
| "You are viewing this account configuration in read-only mode" | Credential ownership. Log in as the owner or use a shared domain credential (<KB id={422606} />). |
| `certificate_unknown(46)` on 9.0.0 or 9.0.1 | Restart logs nodes, or the forwarder container on a collector (<KB id={424877} />). |
| vCenter logs stop after upgrading vCenter to 9.1 | Re-enable collection on Configure Collection (<KB id={433089} />). |
| Banner "logs are getting dropped" with zero drops on the dashboard | A false positive from a tight dynamic threshold (<KB id={451758} />). |
| No ingestion after restoring to a rebuilt runtime | The documented post-restore step (<KB id={436904} />). |

## Network and flow collection

- **Activate it on the vCenter or NSX account** with the "Activate Network & Flow Collection" option, which creates its own credential.
- **If NSX was added by IP** in VCF Operations for networks, enabling it fails with "Adapter instance successfully saved but failed to enable Network and Flow Collection feature". Delete the IP-based source, wait two hours, re-add by FQDN (<KB id={448643} />).

<Callout type="field">
Before a vCenter 9.1 upgrade, screenshot the log collection configuration for each vCenter. Re-enabling it afterwards takes minutes when you know what was there, and the gap in logs is visible to auditors.
</Callout>

## Pitfalls

- **Adding data sources by IP** anywhere. FQDN everywhere.
- **Sending SDDC Manager logs through the default unified proxy** in 9.1.1. That path needs an advanced unified proxy.
- **Using third-party Logs content packs** after 9.1. Convert them to management packs.
