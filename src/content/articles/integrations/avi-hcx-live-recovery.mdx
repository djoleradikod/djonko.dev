<InShort>
HCX is the only one of the six that a VCF subscription includes. The other five are separate purchases on four routes (<AsOf date="2026-11-07" />):

- **Signed file through License Hub:** Avi and vDefend, sharing one appliance. Build it before NSX reaches 9.1.
- **By order line:** Live Recovery.
- **Key in Tanzu Hub:** Tanzu Platform's Elastic Application Runtime, from 10.2. Nothing names a route for 11.0's Apps on VKS, so ask.
- **Unstated since 4 Nov:** DSM. Get it in writing before designing on it.

The one hard product date is 30 May 2027, for NSX Load Balancer use under Avi licences. Keep vDefend and Tanzu out of a VVF design for now, because Broadcom's documents split on both.
</InShort>

<Callout type="note" title="Corrected on 7 November 2026">
This note used to say Avi deploys from SDDC Manager, that Avi, vDefend, Tanzu Platform and DSM all keep keys, and that Live Recovery is partly SaaS, resting on a June 2025 post. VCF Operations now deploys Avi, Avi and vDefend have moved to signed files, and Live Recovery has an on-premises offering. KB 440630 sends readers to the upgrade guides for the full sequence, so it can't carry the upgrade order it was cited for; use [the upgrade order note](/vcf/library/upgrades/upgrade-order-changed/).
</Callout>

This isn't purchasing or legal advice, and your order document decides what you hold.

## License Hub comes before the NSX upgrade

Once NSX is on 9.1 with no hub, adding or changing a distributed firewall policy fails with "This feature is not supported with the current applied license", until a hub is deployed and synchronised (<KB id={446503} />). So the hub goes into the plan ahead of NSX. Avi has more slack: upgrading to 32.1.1 opens a 90-day window to convert, and Controllers already on the Avi Cloud Console aren't affected.

Plan one appliance for both products. It needs 6 vCPU, 12 GB RAM and 256 GB disk and takes up to 120 endpoints. Version 2.0 is the newer one despite the number, and 5.1.2 has no in-place upgrade: <KB id={450105} /> is an export, uninstall and import. vDefend's 13 Oct notes still name 5.1.2, while the [29 Oct hub notes](https://techdocs.broadcom.com/us/en/vmware-security-load-balancing/vdefend/license-hub/2-0/release-notes/license-hub-20-for-vmware-vdefend-and-avi-load-balancer-release-notes.html) require 2.0, so follow the later page.

A disconnected site gains a second manual duty, because the hub reports every 180 days on its own schedule beside the [VCF licence cycle](/vcf/library/licensing/180-day-cycle/).

## Avi must be ready before Supervisor

Activate a Supervisor without Avi integration in place and it [defaults to the NSX load balancer](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-library/vcf-load-balancing-detailed-design/avi-load-balancer-detailed-design.html). Count Controller clusters by NSX Manager, since one cluster maps to one manager and that manager can serve several workload domains. Who has to act by 30 May 2027, and the Service Unit arithmetic, are in [the NSX Load Balancer note](/vcf/library/integrations/nsx-lb-to-avi/).

## vDefend on VVF

Keep it out of a VVF design until Broadcom confirms the mark in writing. FC p17 marks VVF, but AS doesn't, and the NSX alarm in <KB id={438228} /> accepts a vDefend key only alongside a valid VCF key. [Security tiers](/vcf/library/architecture/security-tiers/) covers when you need it at all.

## HCX: included, but it sets the order

HCX and every Service Mesh appliance go to 9.1 or newer before vCenter does, because older 4.x appliances can crash the new vCenter gateway service (<KB id={450437} />). A pairing with VMware Cloud on AWS stops the upgrade: HCX 9.x isn't supported there, with no timeline. <KB id={450437} /> only holds vCenter below 9.1, but <KB id={449276} /> says not to move a connected environment to VCF 9.x at all, so follow the stricter one for now.

A VVF site gets evaluation mode only: 90 days and 20 migrations per migration type, then Restricted Mode, unless its pair holds a valid licence ([HCX guide](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/workload-mobility/vmware-hcx-user-guide-vcf-9-0/preparing-for-hcx-installations/hcx-activation-and-licensing/about-hcx-licensing.html), 5 Nov).

## Live Recovery

This is the line for proving a restore point clean. Core already covers vSphere Replication and vSAN replication (FAQ Q78-79), and [the recovery note](/vcf/library/integrations/dr-and-cyber-recovery-choice/) decides between those, Site Recovery Manager and planned native DR, including where the sources conflict on RPO.

## DSM and Tanzu: what to get in writing

Since 9.1.1 DSM is ["a native VCF Service"](https://blogs.vmware.com/cloud-foundation/2026/09/15/announcing-vmware-data-services-manager-9-1-1/) you can [start from VCF Automation](https://cormachogan.com/2026/09/04/announcing-vmware-data-services-manager-9-1-1/), which rolls out the provider appliance and the Consumption Operator on the Supervisor; Hogan notes standalone remains a deployment model. Its engines are PostgreSQL, MySQL and SQL Server. The [31 Aug TrueSource release](https://mfn.se/all/a/broadcom/broadcom-strengthens-spring-security-and-adds-coverage-of-java-python-and-node-js-ecosystems-with-truesource-e37fa20b) describes Data Services as PostgreSQL, RabbitMQ, MySQL and Valkey, offers "tiered site licensing options" across TrueSource, and doesn't name DSM. So ask three things before renewal: the metric, whether SQL Server stays covered, and whether a DSM deployment still needs a VCF primary licence on vCenter, as the 25 Sep guide's alerts require. [The portfolio note](/vcf/library/licensing/november-2026-portfolio/) has the rest.

For Tanzu Platform, ask how 11.0's Apps on VKS is licensed. The key rule on the Tanzu Hub 11.0 page (22 Oct) names only Elastic Application Runtime 10.2 and later, and the 11.0 release notes (6 Nov) leave licensing out. A TKGi estate has a harder problem: TKGi 1.2x is "entirely incompatible" with VCF 9.1 and NSX 9.1, with no in-place conversion to VKS (<KB id={446224} />). So workloads move first.
