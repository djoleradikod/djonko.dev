<InShort>
**Avi Load Balancer** is deployed from SDDC Manager and integrated with NSX. It still uses license keys, it sits early in the 9.0 to 9.1 upgrade order, and its passwords are managed through SDDC Manager (use **Remediate**, not Update, when only the stored value is stale) (<KB id={442998} />). **HCX** registers with vCenter, has its own vSphere Client plugin, and needed the 9.1.1 management pack for monitoring (<KB id={437447} />, <KB id={454432} />). **Live Recovery** (Site Recovery and vSphere Replication) registers plugins in vCenter, needs FQDN-based certificates, and sits near the start of the upgrade order (<KB id={426469} />). Plan each as its own integration, with its own owner.
</InShort>

## Where they sit in the 9.0 to 9.1 order

The official order puts **VCF Operations first, then vSphere Replication, then Avi**, before SDDC Manager and the management services (<KB id={440630} />). HCX is upgraded with the core of each domain, before NSX and vCenter. Check each product's interoperability for the target release before planning the window.

## Typical integration failures

| Product | Symptom | Pointer |
|---|---|---|
| Avi | "Avi Load Balancer Controller is not reachable" in NSX after a certificate replacement | Reboot controllers until the cluster is stable, then remediate passwords (<KB id={442998} />) |
| HCX | Plugin shows "no healthy upstream" | Connectivity or authentication between HCX Manager and vCenter (<KB id={321631} />) |
| Live Recovery | Plugin "no healthy upstream" or "526 Invalid SSL Certificate" | Certificates generated with a short name. Regenerate with the FQDN (<KB id={426469} />) |
| Live Recovery | Plugin undeploys after about 30 minutes | A stale cached plugin package (<KB id={417767} />) |
| Site Recovery and Replication | "no healthy upstream" after a vCenter update | Reconfigure the appliances with FQDNs (<KB id={382440} />) |

<Callout type="field">
For each add-on, write a one-line integration contract: what it registers in vCenter, what it needs from NSX or SDDC Manager, which licence it uses, and where it sits in the upgrade order. Without it, an upgrade plan can leave a gap at the add-ons.
</Callout>

## Pitfalls

- **Assuming add-ons inherit the VCF license file.** Avi, vDefend, Tanzu Platform and Data Services Manager still use keys.
- **Upgrading the core before replication or Avi** in the 9.1 path.
- **Short-name certificates** on recovery appliances.
